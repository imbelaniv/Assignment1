Background 

 

EventEase, an up-and-coming event management company, coordinates a variety of events across different venues. Due to rapid growth and increasing demand, EventEase has been overwhelmed with managing multiple venue bookings, scheduling, and handling booking conflicts. Currently, all scheduling and bookings are managed manually, leading to double bookings, last-minute cancellations, and a lack of visibility into venue availability. 

 

EventEase has contracted your development team to build an efficient, user-friendly online booking platform to streamline these processes. This application should simplify venue management, prevent booking conflicts, provide a clear view of scheduled events, and enable guests to book venues based on availability. The app should also offer search and filtering capabilities to make it easy to view and manage bookings. 

 

The first phase of the project is building the admin platform, so customers will not be able to make bookings themselves. They can email, call, or walk in and request to make a booking, and from there, one of the booking specialists will use the system to make the booking for the customer. It is possible for an event to be loaded onto the system prior to a venue becoming available, so that once the venue does become available, the booking can be made. 

 

The CEO of EventEase has provided the following requirements that must be present for the new Venue Booking System: 

EventEase needs a user-friendly web application that allows the booking specialists to browse available venues, view events, and make or manage bookings. 

The system should allow authorised personnel to create, view, update, and delete venue and event information, with secure handling of image uploads for each venue. 

Prevent double bookings for venues and restrict deletion of venues or events associated with existing bookings. 

Ensure that all booking information is stored securely in the cloud, with backups. 

Some important information to be stored includes the locations, capacity, venue/event names, start and end dates, and unique booking IDs 

 

EventEase envisions a future where this platform integrates with additional cloud services, allowing seamless scaling as their needs grow. 

 

Introduction 

 

You will build a Venue Booking System for EventEase using ASP.NET Core MVC, deployed in stages to the cloud. The application will follow three main development phases, each building upon the previous phase, to progressively introduce core functionalities and cloud services. 

 

Development Phases: 

Part 1: Project Foundation and Initial Deployment 

Database Design: 

Develop an Entity-Relationship Diagram (ERD) that includes the following tables: 

Venue: Contains details such as VenueId, VenueName, Location, Capacity, and ImageUrl. 

Event: Contains event-specific data, including EventId, EventName, EventDate, Description, and VenueId. 

Booking: An associative table linking Venue and Event (containing BookingID, EventID, VenueId, BookingDate) 

You may add additional tables, but keep the structure simple, ensuring it covers the base requirements without overcomplicating the schema. 

Initial Application Development: 

Create an ASP.NET Core MVC project with models for Venues, Events, and Bookings. 

Build the application with necessary controllers, views, and initial CRUD functionality to the database. 

For images, use placeholder URLs (links to sample images) for venues and events in this phase. 

Deploy Initial Version to Azure: 

Deploy the web app to Azure using the Azure Web App Service. 

Set up an Azure SQL Database to store venue, event, and booking information and migrate your local data to your Azure SQL Database. 

 

 

 

 

 

 

Part 2: Enhancing Functionality and Integrating Cloud Storage 

Error Handling and Validation: 

Implement validation rules to prevent double bookings for the same venue on the same date. 

Add logic to restrict the deletion of venues or events associated with active bookings, displaying an alert to the booking specialist if an action would affect existing bookings. 

Image Management with Azure Blob Storage: 

Replace placeholder URLs with image upload functionality, storing images securely in Azure Blob Storage for Venues and Events. 

Enhanced Display and Search: 

Develop a consolidated view to display bookings more effectively. 

Add a search feature to browse venues, events, and bookings by various criteria. 

Azure Deployment Updates: 

Deploy the updated web application with blob storage integration. 

 

Part 3: Advanced Filtering, Reporting, and Documentation 

Filtering and Event Type Integration: 

Add a new EventType lookup table with predefined categories (e.g., Conference, Wedding, Concert, etc.) to classify events. 

Enhance the search functionality to filter results by event type, venue, date range, and availability. 

Final Deployment and Reflective Report Write-Up: 

Ensure that the fully updated application is deployed to Azure with all the functionality from Parts 1 and 2 and that students understand how the app components interact with Azure services. 

For the final assessment, you will submit a report reflecting on your experience while building the EventEase system using a host of Azure-based services and tools. In this report, you will explain how each service contributed to the app's functionality and performance. 

 

By the end of this project 

EventEase should have a fully functional Venue Booking System with essential features, from event, venue, and booking management to cloud-stored images and filtering capabilities. This project is going to prepare you for more complex projects based on cloud-based systems.
